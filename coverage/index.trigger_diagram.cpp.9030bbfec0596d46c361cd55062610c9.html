1 // The Screen > Combo Triggers diagram: draws a trigger_graph (core/trigger_graph.cpp) the way
2 // the combo triggers guide draws its diagrams. The dialog that hosts it, and gives it each
3 // card's icon and title, is zq/dialog/screen_triggers.cpp.
4 //
5 // Drawing: the widget's DIALOG proc (trigger_diagram_proc) only fills its box on the 8-bit
6 // screen. Everything else is drawn with Allegro 5 on a true-color dialog layer (add_dlg_layer,
7 // like QuestListView) whose render_cb is render(), so the chips get the guide's colors and the
8 // lines are antialiased. markDirty() flags that layer to be drawn again.
9 //
10 // Layout: setGraph() calls layout() once, which works out every rect and line in the diagram's
11 // own coordinates, (0, 0) at its top-left; render() and the hit tests only offset them by the
12 // view's position and scrollX/scrollY.
13 // - A card stacks its header and then each trigger's chips: notes, causes, conditions,
14 // effects and the effects of a failed condition, one chip per line of the trigger, with
15 // small arrows between the groups.
16 // - Each chain of combo changes is a row of cards. The hubs are a column on the left, each
17 // level with the first line that leads to it, and each with its own vertical lane.
18 // - A combo change is a solid arrow to the next card, or over the top of the row to any
19 // other. A link runs left from the chip that names its hub to the hub's lane; from a card
20 // that isn't first in its row, it goes down under the row first. Its arrowheads are the
21 // link's reads (at the card) and writes (at the hub).
22 // drawDiagram() draws the laid out diagram at any offset, which is how Save as PNG draws all of
23 // it into a memory bitmap instead of only what's scrolled into view.
24 //
25 // Text and bitmaps are drawn at whole pixels (draw_text, draw_bitmap). The font is pixel art,
26 // and at a fractional scroll position its glyphs lose rows and columns.
27 //
28 // The picture is of the screen, or every screen of its scrolling region, and has its own zoom
29 // and pan (pictureView, in the picture's pixels); toPicture() maps a point of the widget onto
30 // it. The card placements the dialog gives are in the picture's pixels too.
31 //
32 // Input, in trigger_diagram_proc: the wheel scrolls the list or the diagram, or zooms the
33 // picture. The horizontal wheel has no message, so MSG_IDLE watches mouse_w for it, and also
34 // tracks the hover. A left drag pans the diagram or the picture, and a left click on a list row
35 // or the picture scrolls to that card. Clicks that the dialog acts on (a card, to open the
36 // Combo Editor; another screen of the region in the picture; a hub's note about the region's
37 // other screens) set `action` and raise geCLICK, which onEvent() passes to the dialog's
38 // function for it: the proc can't rebuild the dialog it's running in. A right click opens
39 // contextMenu().
